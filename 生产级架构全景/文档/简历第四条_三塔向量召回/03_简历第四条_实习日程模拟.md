# 简历第四条 · 实习日程模拟（约 6 天）

> 标准：能讲清三塔/双通道、挂在 `item_search`、Faiss 选型、+22%/+35% 口径、跑通 demo。

---

### 第 1 天：关键词为何不够

画三格：同义 miss、场景意图、同 query 不同人。  
**坑**：以为 Agent Prompt 能替代召回。→ 候选池上限在召回。  
**验**：30 秒说清「向量空间近邻」。

---

### 第 2 天：三塔分工 + 和 Store

Query / User / Item 各编码什么；Item 离线。  
Store 文本注入 vs User 塔行为向量。  
**坑**：把「不要塑料」只塞进 User 塔或只塞进 Store。→ 两层互补。  
**验**：一句话各说清一层。

---

### 第 3 天：双通道运行时

语义始终开；有 user_id 开个性化；两路 ANN 并集。  
跑 demo：Query-only vs 个性化排序差。  
**坑**：个性化把完全不相关商品顶上来。→ 语义通道保底。  
**验**：指着 demo 解释为何高端用户仍先看到收纳类。

---

### 第 4 天：ANN + 后过滤红线

Faiss HNSW+IP；多召再滤 platform。  
**坑**：「先滤平台再 ANN」或「滤掉的还能捞回」。→ 截断不可逆。  
**验**：口述为何 fork 四平台或 over-fetch。

---

### 第 5 天：链路位置 + 数字口径

挂点：`item_search`；后面 Rerank/Picker；和① fork 的关系。  
背 `01` §5：+22% / +35%；与 Cache 成本 -35% 分清。  
**坑**：谎称原文有对比表。→ 主动说自拟。  
**验**：默写两个定义公式。

### 第 6 天：串词 + 自我鉴定

录音 30 秒 + 2 分钟；过一遍追问表。  
**鉴定**：

- [ ] 三塔各自干什么  
- [ ] 双通道为何解耦、运行时怎么合

- [ ] 后过滤红线

- [ ] +22% / +35% 诚实可辩护  
- [ ] demo 能讲解  

**验收台词**：  
> `item_search` 里用三塔把 Query/User/Item 编到同一空间，语义和个性化双通道各自 ANN 再合并；召回层 Faiss。相对 Query-only，离线 Recall@100 大约 +22%，跨语言子集大约 +35%。这是组内口径。ANN 截断后过滤救不回，所以要多召或按平台拆。Store 管文本偏好，User 塔管行为向量，不是一层。
