## 2. 起步：追通一次「请求」（全景版）

简历里的 FastAPI / WebSocket 在全景是**目标形态**（见 `00_项目地图.md`、`app/api/` 背景板）。  
理解 Agent 内核时，把入口记成：

```text
（目标）User → React → WS/HTTP → FastAPI
        ↓
（全景已精讲）run_agent(query, thread_id)     ← app/agent/main_agent.py
        ↓
build_agent() = create_agent(
        llm + system_prompt + FULL_TOOL_SET
        + InMemorySaver + middleware)
        ↓
Main AgentLoop Think/Act
        ↓ 若跨平台
dispatch_tool(demands)                      ← app/agent/dispatch_tool.py
        ↓
enter_fork() 深度+1                         ← app/agent/fork_guard.py
        ↓
同一 build_agent()，新 sub-thread_id，子 recursion 更小
        ↓
子 Agent 内调 item_search 等                 ← app/tools/*（背景）
        ↓
只把最终 str 回主 Agent（Observation）
        ↓
PriceCompare / ShippingCalc（不 fork）
        ↓
ItemPicker → ShoppingSummary
        ↓
（②）步进后 Cache Breakpoint；会话末 Reflect → Store
        ↓
（③）trace → eval
```

### 2.2 作业 A（交卷标准：用自己的话答）

1. 主/子是否共用同一个 `build_agent()`？State 靠什么隔离？  
2. 主 `recursion_limit` 与子大约多少？各防什么？  
3. fork 超深时，主 Agent 收到的是异常炸穿还是可读拒绝串？  
4. `dispatch_tool` 算不算九大业务工具之一？它和 `item_search` 分工？  
5. 全景里 **300s 超时**为何和「已落地的 30 轮」不在同一实现档？到哪份文档对齐目标形态？
