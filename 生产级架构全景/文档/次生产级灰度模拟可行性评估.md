> 日期：2026-08-09

---

## 1. 结论

**可以模拟「灰度上线的次生产级 Agent」的主体架构与简历四条，但仅靠原文档 + 现有能力地图骨架，撑不起完整的灰度运营闭环。**

更精确的目标表述是：

> **原文档支撑的 Agent 核心 + 为灰度上线补齐的运营层（讲解版）**  
> 而不是「原文档本身就是灰度生产方案」。

原文档第 15 章已写明端到端跑通之后：「上线前还需要补限额、容灾、观测、安全、评测训练等生产化能力。」这不是我们额外苛刻，是原文自己划的边界。

---

## 2. 「次生产级灰度」的工作定义

本项目采用的次生产级标准（理解与面试可讲，不要求真上生产）：

| 必须能讲清 | 不要求做成 |
|---|---|
| 端到端业务链路与简历四条机制 | 真实四平台授权与生产数据采买 |
| 质量 / 延迟 / 成本 / 错误 四轴指标定义 | 完整 SRE、多租户、真实限流集群 |
| 能力级 feature flag 与回滚矩阵（讲解） | 自动化放量平台、真实 A/B 实验平台 |
| 评测作为发版/放量门禁的角色 | 完整 Agentic RL 训练集群 |
| 单进程 demo 与多实例灰度的差距 | 生产级鉴权与合规审计全套 |

业界灰度通常同时盯四条轴：

1. **质量**：Rubric / Judge、召回指标  
2. **延迟**：任务完成时间、P50/P99、fork 并行收益  
3. **成本**：token、Prompt Cache 命中、工具调用次数  
4. **错误率**：超时、空召回、工具失败、取消  

再加上：**feature flag（部署 ≠ 放量）**、分阶段放量、明确回滚动作（优先改配置，不紧急改代码）。

## 4. 真正欠缺什么

### 缺口 1（最大）：灰度运营层

原文档几乎没有一等公民的：

- 能力级 feature flag / kill switch  
- 放量阶段与自动升量 / 回滚阈值  
- 任务级统一观测（不等于 AGUI 推前端）  
- 配额与限流  
- 安全边界（鉴权、注入、脱敏；Rubric P0 只提了「泄露内部 ID」）

**处理**：在全景中新增 `app/ops/`（讲解为主），见第 6 节。

### 缺口 2：评测未接到发版 / 放量门禁

第 08、13-1 章有评测方案，但骨架里 `app/eval/` 仍是背景板，缺少：

- 固定回归集如何卡发版  
- 灰度中在线抽样评分  
- 「质量掉点 / P0 失败率超阈 → 降流量」的可操作规则  

### 缺口 3：多实例持久化真相讲不够

`InMemorySaver` 多 worker 丢会话、Checkpointer vs Store vs 向量库边界、索引版本 A/B——必须在叙事里写清「单进程 demo ≠ 可灰度多实例」。

### 缺口 4：缺一条贯穿的「上线故事线」

能力地图按模块列文件，适合学架构；灰度还需要：

```text
内部验证 → 小流量 → 看四轴指标 → 升量或回滚
```

### 缺口 5：简历数字口径未全部绑死

| 数字 | 原文档支撑 | 风险 |
|---|---|---|
| 30 轮 / 300s | 第 14 章精确有 | 低 |
| 延迟降约 65% | 串行≈和、并行≈最慢，量级可辩护 | 中（需自测口径） |
| 缓存命中 80% | 第 05 章几乎逐字有 | 低 |
| 记忆命中 72% | 原文档未找到出处 | **高** |
| 召回 +22% / 跨语言 +35% | 原文档未找到该对比数字 | **高** |

### 缺口 6：学习材料边界

本项目以理解为主，不要求系统能跑。灰度最核心的「拨开关 → 看指标 → 回滚」用讲解版 `app/ops/` + 指标定义即可，不强制可运行 stub。

## 5. 已确认的模拟边界

1. **灰度运营层进目录**：`app/ops/`（讲解文件，不是完整实现）。  
2. **不要求最少可拨开关的可运行 stub**：理解为主。  
3. **核心跟原文档；运营壳标明是次生产级补丁**，见《原文档与次生产级差别》。  
4. **不做**：完整多租户、真实四平台授权、完整 SRE、真实 RL 训练集群。

---

## 6. `app/ops/` 补丁目录（讲解版）

```text
app/ops/
├── flags.py          能力级开关与流量百分比（讲解）
├── metrics.py        质量/延迟/成本/错误 四轴指标定义（讲解）
├── rollback.py       回滚矩阵：何种信号关掉哪些 flag（讲解）
└── rollout.md        灰度阶段故事线（内部 → 小流量 → 升量/回滚）
```

角色分工：

- **业务内核**（`agent` / `tools` / `recall` / `memory` / `compress`…）：来自 `globex/`  
- **运营壳**（`ops/`）：原文档缺失、为次生产级灰度模拟补上的讲解层
