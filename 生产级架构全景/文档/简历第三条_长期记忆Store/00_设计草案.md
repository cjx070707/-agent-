## 1. 一句话

Cache Breakpoint 管「这一次会话别爆 token」；Store 管「下次会话还记得不要塑料」。  
存的是**结构化偏好条目**，不是整段聊天记录。

---

## 2. 和①②的关系

| | ① fork | ② Breakpoint | ③ Store |
|---|---|---|---|
| 范围 | 子任务隔离 | 单会话历史 | **跨会话** |
| 对象 | 子 Agent 上下文 | messages | PreferenceEntry |
| 典型收益 | 延迟/主线干净 | 命中率+控 token | 偏好自动生效 |

有了 Store，会话历史可以更大胆压缩——重要偏好不靠「别把旧消息压没」。

---

## 3. 机制要点（粗讲用，见对话）

- 写：会话 Reflect / 检测到新偏好 → 抽取 → `write`  
- 读：新会话或 `run_agent` 开头 → `read_relevant(query, top_k≈5)` → 注入 system prompt  
- 黑名单优先；软衰减降旧偏好权重（黑名单不轻易衰减没）  
- 实现阶梯：内存跑通 → 向量相关读 → Redis/Postgres/OpenSearch 持久化  
- 72%：原文无 → 设计里定为「注入后 ItemPicker/约束命中」类自拟口径，面试诚实说测法
