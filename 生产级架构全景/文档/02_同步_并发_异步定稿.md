# 同步 / 并发 / 异步定稿（次生产级）

> 日期：2026-08-09  
> 状态：**已定稿（方案 A）**  
> 范围：仅约束 `生产级架构全景` 的说法与学习优先级；不绑定任何复刻代码仓库。

---

## 1. 三档定义

| 档 | 名称 | 含义 |
|---|---|---|
| **1** | 全同步串行 | 同轮多个工具也顺序等完；多平台耗时≈各路之和 |
| **2** | 同步 Agent 思维 + 同轮工具并发 | 业务按「Think → 调工具」理解；多平台变快靠主 Agent **同轮多个** `dispatch_tool`，由运行时并发执行 |
| **3** | 全链路异步形态 | `app/api`（HTTP/WebSocket）+ Agent `ainvoke` + `asyncio.wait_for` 真超时/可取消；工具与 IO 与事件循环对齐 |

两件事必须分开：

| 概念 | 解决什么 | 简历①怎么用 |
|---|---|---|
| **并行** | 多路子任务同时推进，墙钟≈最慢一路（~65%） | **主讲、深挖、要会模拟压测** |
| **全异步（第3档）** | 与网关一体、超时真取消、高并发 IO 模型 | **知目标、能口述**；不是把学习重心改成整仓 async 重构 |

有第3档也可以做并行；有并行不等于已经是第3档。

---

## 2. 本全景的正式定位

**生产级架构全景（次生产级）的目标形态 = 第 3 档。**

依据：

1. 全景已包含 `app/api`（FastAPI / WebSocket / AGUI），不是「只讲 Agent、不管接入」的第2档产品形态。  
2. 原文档第14章超时为 `wait_for(ainvoke)`，第15章为异步任务 + WebSocket——次生产级跟原文定稿。  
3. `app/ops` 为灰度补丁，挂在可上线叙事上，默认建立在可接入、可超时取消的形态之上。

**不采用：**

- 把全景最终方案定成第1档或第2档；  
- 把第3档划成「暂不纳入、与全景无关」。

---

## 3. 面试定稿话术（可直接用）

> 次生产级目标是全链路异步接入：FastAPI / WebSocket，Agent 用 `ainvoke`，超时用 `asyncio.wait_for` 做真取消。  
> 跨平台降延迟靠的是主 Agent 同轮多个 `dispatch_tool` 并发执行，墙钟时间接近最慢一路，而不是在业务里写死四路串行。  
> 异步解决网关一体化和超时可取消；并行解决多平台等太久——两件事叠在同一套架构里，不要混成一件事。

禁忌：

- 不要说「因为我们全异步了所以才有 65%」——65% 来自多路并发，不是来自 async 关键字。  
- 不要说「我们只有同步串行」——与同质 fork 并行叙事冲突。  
- 不要把学习重心说成「我主要在做整仓 async 重构」——简历①过线看的是 fork / 护栏 / 并行证据。
