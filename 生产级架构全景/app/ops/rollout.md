# 灰度阶段故事线（讲解版）｜次生产级补丁

> 原文档没有这一章。业务内核仍按 `globex/`；本文件只回答「如果要灰度上线，阶段怎么走」。

## 阶段

```text
0. 内部验证（0% 外部用户）
   -> 固定回归 query + Rubric/召回离线门禁（原文 08 / 13-1 思路）
   -> 确认防失控、超时、关键路径可讲清

1. 小流量（例如 1% 或内部员工）
   -> 打开目标能力 flag（如并行 fork 或三塔）
   -> 盯 ops/metrics 四轴；对照 rollback 矩阵

2. 扩大流量（例如 10% → 25% → 50%）
   -> 每一档停留足够观察窗口
   -> 质量/延迟/成本/错误任一跌破约定 → 停升量，执行 rollback

3. 全量或保持灰度
   -> 保留 kill switch
   -> 持续抽样评测 + 召回看板（原文有局部，运营层补任务级）
```

## 每一阶段「看哪些文件」

| 阶段问题 | 先看 |
|---|---|
| 链路对不对 | `app/agent/`、`app/tools/`、`app/api/`（原文） |
| 简历能力开没开 | `app/ops/flags.py`（补丁） |
| 数字有没有掉 | `app/ops/metrics.py` + 原文 05/08/13-1 指标 |
| 要不要撤 | `app/ops/rollback.py`（补丁） |

## 和原文的边界一句话

原文把你送到「能端到端跑、有局部降级和评测方案」；本故事线把你送到「能模拟怎么放量、怎么停」。两者叠在一起才是本项目的「次生产级灰度」定义。
