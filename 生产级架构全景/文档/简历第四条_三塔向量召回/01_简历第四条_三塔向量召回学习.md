## 1. 面试介绍

### 1.1 30 秒

`item_search` 底层不是关键词包含。我们用 User / Query / Item 三塔把长期偏好、即时意图和商品编码到同一向量空间，语义通道保相关性、个性化通道保转化，两路各自 ANN 再合并。召回层用 Faiss（HNSW + IP）扛高 QPS。离线相对 Query-only，Recall@100 大约 +22%；跨语言子集大约 +35%——这是组内评测口径。召回上限定了，后面 ItemPicker 再聪明也救不了烂候选。

### 1.2 2～3 分钟

**痛点**：同义（收纳袋≈整理包）、场景意图、同 query 不同人结果应不同——BM25 扛不住。  
**三塔**：Query=这次搜什么；User=长期爱什么；Item=商品是什么。Item 离线灌库；在线只编 Query（+User）。  
**双通道**：语义路只看 query↔item，防个性化把相关商品挤掉；个性化路用 user⊕query，提高转化。运行时两路并行 ANN，并集去重。  
**基础设施**：召回层 Faiss 纯向量；应用层记忆/RAG 用 OpenSearch——延迟与过滤需求不同（04-1）。  
**红线**：ANN 截断后平台过滤捞不回 → 多召一点再滤，或按平台拆 fork。  
**和 Agent**：fork 四平台时每个子 loop 调一次 `item_search(platform=…)`；三塔是工具内部。  
**和 Store**：Store 是文本偏好注入 prompt；User 塔是行为向量进 ANN——互补，不是同一层。  
**和 Rerank**：bi-encoder 物理上限 → Top-100 后再 cross-encoder 精排（背景，不深挖）。

### 1.3 追问速答

| 问 | 答 |
|---|---|
| 为何不是双塔？ | 长期偏好 ≠ 本次意图；拆 User/Query 才解耦 |
| 双通道为何不合成一个 loss？ | 相关 vs 转化梯度常冲突；解耦后可独立保底 |
| 为何 Faiss？ | 百万～千万 SKU、纯 ANN、P99 紧；记忆/RAG 过滤多 → OpenSearch |
| 后过滤？ | ANN 没召回的商品后续滤不回来；要多召或分平台检索 |
| +22% / +35%？ | 自拟相对提升；定义见 §5，不谎称原文表 |
| 和关键词？ | 同义/跨语言关键词 miss，向量能近邻命中 |
| Item 塔何时算？ | 离线批量；在线只 Query/User + search |

### 1.4 禁忌

- 不要说「Agent 自己做向量检索」——是 `item_search` 内部。  
- 不要把 Store 文本偏好说成 User 塔。

## 2. 机制图

```text
用户: 旅行收纳袋 (+ user_id)
  → 主 Agent → item_search(platform, query, user_id?)
       ├─ 语义通道: QueryTower(query) → ANN TopK
       └─ 个性化通道(有 user): fuse/User⊕Query → ANN TopK
  → 并集去重 / 轻量重排 → Candidate[]
  →（背景）Reranker Top-10 → ItemPicker
```

04-0 公式直觉（编码侧）：

```text
request ≈ normalize(α·query_vec + β·user_vec)   # 个性化请求向量
hits = ANN(request, ItemIndex, top_k)
```

11 章工程落地更常是「两路各自 ANN 再并」——面试两套都能说，优先讲清**运行时双通道**。

## 5. +22% / +35% 口径（背这个）

### +22%（召回）

**定义**：同一离线评测集上，  
`Recall@100(三塔 + 双通道)` 相对 `Recall@100(Query-only 单塔，无 User / 无个性化通道)` 的**相对提升**：

```text
(+22%) ≈ (R_tri − R_query_only) / R_query_only
```

例：0.70 → 0.85 ⇒ (0.85−0.70)/0.70 ≈ 21.4% ≈ **22%**。

**原文可借的量级**：04-2 训练阶梯 Recall@100 约 0.62→0.88，说明向量召回可大幅抬升，但**不是**「+22% vs 单塔」那张对比表。

### +35%（跨语言）

**定义**：中英混合 / 跨语言 query–title 子集上，带跨语言对齐的三塔相对「朴素单语 embedding / 关键词」的 Recall@K **相对提升**约 35%。

**原文可借**：04-2 有跨语言对齐 loss 与跨语言指标；**没有**「+35%」官方表。  
**口误防火墙**：05 章「综合 token 成本 -35%」是 Cache 条，别串台。

**面试补一句**：数字是组内离线口径；机制（三塔+双通道+ANN）比数字更重要；若对方追问实验，能复述对照与指标即可。
